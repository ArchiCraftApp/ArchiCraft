# AS-05 crash recovery: manual procedure

SRS AS-05: force-terminate the application six minutes after the last save, while editing. On
restart the user is offered recovery, the recovered model contains everything up to the last
autosave, and the original file is intact. It re-verifies PRJ-004, PRJ-005, NFR-REL-001 and
NFR-REL-002 and must pass on Windows, macOS and Linux.

CI runs the same scenario on all three operating systems with a virtual clock:
`as05_crash_recovery` in
[crates/archicraft-app/tests/crash_recovery.rs](../../crates/archicraft-app/tests/crash_recovery.rs)
starts the application in a child process, kills it and restarts it. That test runs the
application without a window. This procedure covers what it cannot: the windowed binary, real
time, the operating system's own way of killing a process.

## Setup

1. Build the release commit: `cargo build --release --locked -p archicraft-app`. The binary is
   `target/release/archicraft` (`archicraft.exe` on Windows).
2. Use an empty data folder, so that earlier sessions do not show up: set `ARCHICRAFT_DATA_DIR`
   to a new folder, for example `<tmp>/as05-data`. Autosaves go to its `recovery` folder.
3. Use an empty project folder elsewhere, for example `<tmp>/as05-project`.

Start the application with the variable set:

- Linux and macOS: `ARCHICRAFT_DATA_DIR=/tmp/as05-data target/release/archicraft`
- Windows (PowerShell): `$env:ARCHICRAFT_DATA_DIR="$env:TEMP\as05-data"; target\release\archicraft.exe`

Check under File → Preferences… that autosave runs every 5 minutes (the default, Appendix D.1).

## Steps

Keep a clock at hand; times are from the save in step 2. The autosave interval runs from the
start of the application, so do steps 1 and 2 within the first minute after starting it.

1. Draw two walls with the Wall tool.
2. **Minute 0:** save as `house.ifcx` in the project folder. Draw a third wall and save again,
   so that the folder holds `house.ifcx` and its backup `house.ifcx.bak`. Copy `house.ifcx` to
   a place outside the project folder for the comparison in step 9.
3. **Minute 1:** draw wall A.
4. **After minute 5:** check that `recovery/session-…/autosave.ifcx` exists in the data folder.
   It holds wall A.
5. **Minute 5.5:** draw wall B (after the autosave, so it is lost by design).
6. **Minute 6:** while the Wall tool is still active, force-terminate the process:
   - Linux: `kill -9 $(pgrep -x archicraft)`
   - macOS: `kill -9 $(pgrep -x archicraft)` (or Activity Monitor → Force Quit)
   - Windows: `taskkill /F /IM archicraft.exe` (or Task Manager → End task)
7. Start the application again with the same `ARCHICRAFT_DATA_DIR`.

## Expected

8. The "Recover unsaved work" window lists the project with the autosave time and the path of
   `house.ifcx`. Click **Recover**. The model shows the three saved walls and wall A, not
   wall B. The title reads `● house.ifcx — ArchiCraft`: the changes are unsaved.
9. `house.ifcx` is byte-identical to the copy from step 2 (`cmp` on Linux and macOS,
   `fc /b` on Windows). The project folder holds only `house.ifcx` and `house.ifcx.bak`.
10. The data folder's `recovery` folder holds only the session of the running application;
    the killed session's folder is gone.
11. Close without saving. No recovery is offered at the next start.

Record the outcome per operating system in the
[release checklist](release-checklist.md#3-as-05-crash-recovery-on-windows-macos-and-linux).
